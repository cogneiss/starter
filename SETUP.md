# Development Setup

## Prerequisites

```bash
composer install   # also wires up the shared git hooks
bun install
```

Laravel Brain ships as a dev dependency, so `composer install` already has it.
Three more tools are optional; install them for graph-backed search and impact
analysis (recommended — they save a lot of time and a lot of AI tokens):

```bash
pip install "graphifyy[gemini]"  # knowledge graph extraction
pip install code-review-graph    # call graph + impact analysis
npm i -g gitnexus                # execution flows + blast radius
```

Everything below degrades gracefully. If the tools are not installed, the hooks
detect it and exit quietly.

### Graphing the docs (optional)

Code is extracted locally with tree-sitter and needs no API key. Markdown —
`CLAUDE.md`, `AGENTS.md`, `.ai/rules/`, the skill files — is extracted by an LLM
and does need one. Without a key, `graphify .` fails; pass `--code-only` to skip
the doc layer, or export a key to include it:

```bash
export GEMINI_API_KEY='...'   # aistudio.google.com/apikey, free tier is plenty
graphify .                    # ~$0.05 for a full repo pass, then incremental
```

Install the `[gemini]` extra shown above, not bare `graphifyy` — the gemini
backend talks over the OpenAI-compatible endpoint and errors out without it.
`uv` users: `uv tool install "graphifyy[gemini]" --force`.

A run may report that some files "produced no nodes"; the model occasionally
omits them. Just run `graphify .` again — it retries only the missed files.

## Git hooks

`composer install` runs the `hooks:install` script, which points git at the
committed hooks in `.githooks/`:

```
git config core.hooksPath .githooks
```

Nothing else to do. To verify: `git config core.hooksPath` should print
`.githooks`.

After every commit, `.githooks/post-commit` refreshes four graphs so they stay in
sync with the code:

| Command | Output | Log (under `~/.cache/`) |
| --- | --- | --- |
| `graphify` incremental rebuild | `graphify-out/` | `graphify-rebuild.log` |
| `code-review-graph update` | `.code-review-graph/graph.db` | `code-review-graph-rebuild.log` |
| `gitnexus analyze . --skip-agents-md` | `.gitnexus/` | `gitnexus-rebuild.log` |
| `php artisan brain:scan` | `storage/app/laravel-brain/` | — (foreground) |

The first three run detached, so `git commit` returns immediately. `brain:scan`
runs in the foreground because it needs the app booted, but it finishes in under
a second. Set `GRAPHIFY_SKIP_HOOK=1` to skip a rebuild for one commit.

`--skip-agents-md` is not optional: without it, `gitnexus analyze` rewrites
`AGENTS.md` and `CLAUDE.md` on every commit to tell agents to use its MCP server,
which this repo deliberately does not run (see below).

The graphify portion of the hook is generated by `graphify hook install`.
Regenerate it rather than editing it by hand.

All four output directories are gitignored — they contain absolute machine paths
and are cheap to rebuild. (`storage/app/laravel-brain/` is covered by Laravel's
own `storage/app/.gitignore`.)

## Regenerating the AI guidelines

`boost.json` records which agents and skills are installed. To refresh the
generated guideline and skill files after a Boost or package upgrade:

```bash
php artisan boost:install --guidelines --skills --no-interaction
```

Pass both flags. `--guidelines` on its own drops the "Skills Activation" section
from `AGENTS.md` and `CLAUDE.md`; adding `--skills` puts it back.
`php artisan boost:update` also works and preserves that section.

Neither command writes `GEMINI.md`, even though `gemini` is still listed in
`boost.json` — Boost dropped it from the agents it renders, so it goes stale
without warning. Re-sync it by hand afterwards:

```bash
cp AGENTS.md GEMINI.md
```

## Wiring the graphs into your AI editor

Nothing to wire. `.ai/rules/general.md` routes AI agents to the CLIs, and every
agent reads that file automatically.

Each tool also ships an MCP server (`graphify claude install`,
`code-review-graph install`, `gitnexus setup`). Skip them. An always-on MCP
server re-sends its tool schemas on every conversation turn and every subagent
spawn — roughly 500 tokens per tool, paid whether or not you use it. The CLIs
cost nothing until invoked, which is the whole point of this setup.

## Using the graphs

The rules in `.ai/rules/general.md` tell AI agents to reach for these before
searching the codebase file by file. The same commands are useful by hand:

```bash
# Laravel-shaped question? Start here — the only graph that knows routes,
# relationships, listeners and queued jobs. Leading slash on the URI is required;
# without it the command silently dumps the whole project instead.
php artisan brain:export-context --route=/settings/profile --budget=2000

graphify query "how does authentication flow through this app?"
code-review-graph impact SomeClass::someMethod   # what breaks if I change this
code-review-graph architecture                   # high-level module overview
code-review-graph dead-code                      # unreferenced functions
gitnexus context SomeClass                       # callers + callees + processes
gitnexus trace Controller Repository             # shortest path between symbols
gitnexus detect-changes                          # map your diff to affected flows
```

If a command complains the graph is stale or missing, rebuild it directly:

```bash
graphify update .
code-review-graph update    # or: build, for a full re-parse
gitnexus analyze . --skip-agents-md   # incremental; -f forces a full re-index
php artisan brain:scan --no-interaction
```

Laravel Brain also serves an interactive viewer at `/_laravel-brain` (dev only).
Do not run `brain:generate-rules` — it writes a project snapshot into `CLAUDE.md`
and friends, which goes stale on the next commit and is re-read every turn.
`.ai/rules/general.md` is the routing surface instead.
