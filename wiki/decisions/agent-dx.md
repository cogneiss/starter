# Decision log — agent developer experience

The current plan. `todo/agent-dx.status.json` holds the phase list and the exact
command that decides each one; a phase is `passing` only when that command has
been run and was green.

## The problem it addresses

An agent opening this repository can read the rules and infer the code, but
nothing explained _why_ the code is shaped this way — so every session rebuilt the
same reasoning, and a refactor could quietly invalidate documentation nobody
checked. The rules layer is too short to carry it and `FEATURES.md` is a catalogue,
not an explanation.

## The decisions

- **One source for the guideline files.** `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`
  and the editor variants are generated by
  `php artisan boost:install --guidelines --skills`, wired into `post-update-cmd`,
  with a test that fails on drift inside the `<laravel-boost-guidelines>` block
  ([[operations/documentation]]).
- **Documentation rot is a build failure.** `wiki:lint` blocks. A page whose code
  moved on is caught the same way a broken test is
  ([[architecture/fast-blocking-gates]]).
- **`code_refs` are file paths, never directories.** A directory ref matches
  every commit touching anything inside it, so the stale-page rule would fire on
  unrelated work — and a blocking gate that goes red for unrelated reasons gets
  disabled. Rule 1 rejects directory refs for that reason, and the stale
  comparison is at date granularity so a same-day commit is not drift.
- **Status files stay out of `code_refs`.** Measuring the last thirty commits,
  the only pages that went red for a reason a reader would call wrong were the
  two decision logs citing their own `todo/*.status.json`: three commits that
  did nothing but tick a phase off. The refs were dropped rather than the rule
  loosened.
- **Pages are superseded, never deleted.** A wrong page becomes
  `status: superseded` pointing at its replacement, so a link into it still lands
  somewhere true.
- **Never invent behaviour.** Every claim names the file that proves it. Uncertain
  means the page says the behaviour is not documented.
- **Bumping `updated:` alone is the failure mode to watch.** It clears the gate and
  hides the drift, which is worse than the drift. `wiki/_meta/lint.md` says so
  where the fix instructions are.
